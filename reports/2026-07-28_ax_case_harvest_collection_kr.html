3 · 씨드 소스 우선순위

후보 소싱 프롬프트가 실제로 읽는 두 입력

(a) 1순위 — awesome 리스트: awesome_ax-cases.md + 그 상단이 인용하는 원본 awesome-list raw 페이지(보고서 자체 cap을 넘는 항목까지). 단, index/listicle 페이지 자체는 후보로 내지 않고 반드시 전환 스토리를 서술하는 실제 페이지(뉴스·케이스 스터디·기업 블로그)로 resolve.

(b) 2순위 — 검색 hits: search_hits_ax.json. 출처 URL을 특정할 수 없는 항목은 추측하지 않고 버림.

# 후보 소싱 호출의 핵심 지시 (요약)
"Seed sources, in priority order: (a) awesome_ax-cases.md + raw list page(s),
 (b) search_hits_ax.json. Resolve EVERY candidate to the page that actually
 describes the transformation story. Never emit an index/awesome-list page.
 EXCLUDE urls already in attempted_urls[] or an existing case's source_url.
 Return at most BATCH_SIZE. Output ONLY JSON {hits:[{url,title,snippet,domain}]}."
