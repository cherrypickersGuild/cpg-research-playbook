5 · The integrity gate

231 harvested is not 231 verified — and the deck rule is explicit

By the project's own definition, zero cases are deck-ready.

CLAUDE.md: "Validation is a hard gate: never select or present a case that has not passed validation." A validated case carries a gate_passed flag written by Stage 2. No record in the registry has that field, because Stage 2 has never seen this data. Three independent facts confirm the corpus is pre-validation:

  • All 231 are single-sourced. corroboration_count = 1 everywhere; 01_case_finder.md's bar is Tier A, Tier B primary financials, or two independent sources. None is met.
  • "verified" is a fetch status, not a verdict. The 208 "verified" only mean the source URL returned 200. It should be read as fetch_status: fetched | snippet_only.
  • The bridge is missing. The harvest wrote ax_case_harvest_registry.json; Stage 2 reads ax_case_db.json, which is {"cases": []}. The two paths were built separately and never joined.

The attrition when this bridge is built will be heavy and correct: single-sourced, self-published, mostly-undated cases are exactly what the validator exists to filter. The 231 are a strong lead list, not a vetted corpus.

7 · Provenance

When and how the corpus was built
  • Harvested in two days. discovery.first_seen_at is 2026-07-14 for 227 cases and 2026-07-15 for 4. Four run transcripts span 07-14 (three runs) to 07-15 (one).
  • One channel. found_via.platform is "web" for all 231 — no news-monitor, social, or awesome-list contributions reached the registry.
  • 51 URLs attempted, 231 cases kept. The attempted-URL ledger holds 51 entries; a single source page often yields several company cases, which is how 51 fetches produce 231 records.
  • Seed exhaustion. Session memory records both AX-case seeds fully consumed as of 2026-07-15; re-running the harvest as-is returns ~0 new. Growth needs new, higher-tier seeds — not another pass.

8 · What to do with this

In priority order
  1. Build the harvest → pipeline bridge. Populate ax_case_db.json from the registry, then run Stage 2 (ax-validator). Expect — and accept — heavy attrition.
  2. Rename verification_status to fetch_status (fetched/snippet_only) and report source tier separately, so "verified" stops implying a verdict it does not carry.
  3. Fix the seeds before re-harvesting. The single-source, self-published ceiling is set upstream; add Tier-A-first sources so corroboration > 1 becomes reachable.
  4. Treat the 231 as leads. They are a well-structured, named-company lead list with sourced KPIs — the right input to validation, not a substitute for it.
