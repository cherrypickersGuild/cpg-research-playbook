ROOT-CAUSE ANALYSIS · SOURCE QUALITY

Why the AX corpus is almost all low-tier sources

231 harvested cases, 96 domains, zero independent Tier-A outlets. This is not bad luck in what surfaced — it is the deterministic output of the seeds chosen and a harvest path with no concept of source tier. The pipeline could not have produced a high-tier corpus.

SUBJECT harvest_ax_cases.sh · awesome_ax-cases.md · search_hits_ax.json CORPUS ax_case_harvest_registry.json (231 cases) DATE 2026-07-18
Diagnosis

Garbage-tier-in, garbage-tier-out — plus a resolver that strips out what little independence there was.

The primary seed is a curated directory of company engineering blogs, so its entire universe is self-reported. The secondary seed contained almost no independent outlets to begin with. And the harvest path never mentions "tier" once — it has no way to prefer, require, or even notice an independent source. The few Tier-A/C domains that did appear in the seeds were dropped before they reached the registry.

Every case is a company, a vendor, or an individual describing their own success. No Reuters, WSJ, FT, Bloomberg, Economist, HBR, or MIT Sloan appears anywhere in the corpus. There is no independent verification because there is no independent source. The question is why — and the answer is entirely upstream of extraction.

2 · Cause one — the seed sets the ceiling

A harvest cannot produce sources higher-quality than the places it is told to look. The AX harvest has exactly two seeds, and the script consults them in priority order.

The seed is not a flaw in the seed — it is an excellent list of engineering blogs. The flaw is asking it for something it structurally cannot contain. An index of company blog posts has a hard tier ceiling of B (company primary) and D (vendor). It contains zero Reuters, zero HBR, zero SEC filings, because that is not what it curates. Pointing a case harvest at it guarantees a self-reported corpus before a single page is fetched.

3 · Cause two — the harvest path has no concept of tier

The project defines a rigorous four-tier source model — but only in specs that never ran (01_case_finder.md, 02_validator.md). In the path that actually produced the 231 cases, the harvest script never mentions tier at all, and the extractor mentions it exactly once — to say it doesn't do it. Grep the two files that ran:

# scripts/harvest_ax_cases.sh + ax_case_harvest_extractor.md

agents/stage1/ax_case_harvest_extractor.md:9: "…no KPI breakdown, no source-tier
                                                classification, no contradictory-evidence search"

The extractor's only reference to source tier is the line disclaiming it — this is deliberate, a fast net rather than a quality filter:

"deliberately a lighter-weight sibling… no source-tier classification, no contradictory-evidence search. Speed and volume over exhaustive rigor." agents/stage1/ax_case_harvest_extractor.md, lines 8–12

So there is no step that prefers an independent source, requires corroboration for a vendor claim, or even records what tier a source is. Nothing steers the harvest upward, because nothing in it knows "up" exists.

4 · Cause three — the resolver actively pushes down-tier

Worse than tier-blind: the candidate-sourcing instruction contains a rule that systematically prefers the self-reported source over the independent one.

"resolve it to the page that actually describes the transformation story (a news article, case study, or company blog post) — not an index/listicle page." scripts/harvest_ax_cases.sh:277 — the candidate-sourcing prompt

For a self-reported AX story, the page that "actually describes the transformation" is the company's own engineering blog — that is where the numbers, the before/after, and the detail live. An independent outlet typically summarises and often paywalls. So three mechanisms compound, each stripping independence out:

1
Resolve-to-primaryWhen both a company blog and a news write-up exist, "the page that describes the story" resolves to the company blog. The independent coverage is discarded as less detailed.
2
Paywall attritionThe extractor marks an unfetchable page snippet-only and prefers fetchable ones. Reuters/WSJ/FT/HBR are exactly the sources behind paywalls — so they lose to an open company blog every time. (The validator spec fixes this with accessible_with_paywall; the harvest has no such rule.)
3
No corroboration passThe rich case finder says: "For each candidate from a vendor page, run a follow-up query for independent confirmation before including it." The harvest omits this entirely. Every case ends at corroboration_count = 1 — the first source found is the only source recorded.
The proof: the little Tier-A/C that reached the seeds never reached the registry. The secondary seed did contain some higher-tier hits. We traced each one from seed → registry:

5 · The deepest reason — a real domain skew the pipeline ignored

Part of this is genuine, not just a coding gap: AX stories overwhelmingly live on company blogs. Firms publish their own AI wins in detail; independent outlets cover a smaller, more selective slice, later, and often behind a paywall. Tier A is genuinely scarcer and harder to fetch for this exact topic. That reality is precisely why 01_case_finder.md was designed the way it was:

"Start from Tier A/B; use Tier C/D only to discover candidates, then verify upward… a KPI counts as verified only if it traces to Tier A, Tier B primary financials, or two independent sources… Tier D — vendor case studies, press releases — leads only, never a sole source." agents/01_case_finder.md, lines 42–44 & 136–137

Every countermeasure the domain skew demands already exists on paper. The harvest is the version with all of them removed. This corpus is what you get when you run the fast net and skip the pipeline it was meant to feed.

6 · How to resolve it

Ordered by leverage. The first two change what enters; the rest change what survives.

A · Fix the seeds — you cannot filter in what you never sourced highest leverage

  • Add Tier-A-first seeds. Curated query sets and lists that target independent outlets and primary filings: HBR / MIT Sloan case archives, Reuters/Bloomberg/FT technology desks, SEC 10-K/8-K full-text search (EDGAR), NBER / arXiv econ-of-AI. These are the domains 01_case_finder already names — nothing new to invent.
  • Rebalance seed priority. Today the eng-blog directory is priority (a) and dominates by sheer volume. Make independent-outlet seeds priority (a) and use the eng-blog directory as the corroborating second source, not the primary one — the inverse of the current order.
  • Expand the search-hit seed. 14 generic queries yielded 111 hits with almost no Tier A. Tier-targeted queries ("[company] AI" site:reuters.com, site:sec.gov "artificial intelligence") would surface independent coverage the current queries never asked for.

B · Make the harvest tier-aware medium leverage

  • Classify tier at candidate time — a cheap domain lookup adds a source_tier field the extractor currently lacks. You cannot manage what you don't measure.
  • Set per-tier quotas / floors (mirroring the anti-skew quotas already in 01_case_finder): e.g. no more than N% Tier D, a minimum % with an independent source.
  • Add a corroboration pass: for any Tier-D/self-published candidate, run one follow-up query for an independent source before accepting — raising corroboration_count above its current uniform 1.
  • Stop discarding independent coverage. Change the resolver rule to keep both the primary (detailed) source and an independent (corroborating) one, rather than collapsing to the company blog.

C · Run the validator — enforce the tier rule that exists it's built, unused

02_validator.md already encodes "Tier D alone may never anchor a main-deck claim; require Tier A/B or two independent sources" and treats a paywalled Reuters/HBR as usable (accessible_with_paywall), not a reject. Running it will correctly route today's vendor-only cases to appendix/manual_review. But be clear about what this can and cannot do:

The validator filters; it cannot manufacture. It can down-rank the low-tier cases you have — but it cannot create the Tier-A sources that were never sourced. If you validate the current 231 without fixing the seeds first, you will get a correctly-labelled pile of low-tier cases and a near-empty main deck. Fix step A first, then let the validator enforce. Sourcing quality is set upstream; validation only reveals it.

D · Reset expectations on the word "verified"

As the earlier analysis showed, verification_status: "verified" here means only "the page was fetched," not "the claim is independently confirmed." Combined with 0% Tier A, "208 verified cases" currently reads as far stronger than it is. Renaming the field (fetch_status: fetched | snippet_only) and reporting a separate tier-mix stat would stop the corpus from looking more credible than its sources justify.
