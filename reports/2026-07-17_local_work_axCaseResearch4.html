What this project is

The repository holds two connected bodies of work that grew in sequence.

  • A four-stage deck pipeline (declared in CLAUDE.md): Case Finder → Case Integrity Validator → AX Case Selector → Executive Slide Builder. Validation is designed as a hard gate — no case reaches a slide without passing it.
  • A seven-agent Stage-1 discovery system (agents/stage1/1A–1G) that builds search strategies, crawls, extracts cases and entities, monitors news, and schedules refreshes. This is where nearly all the actual engineering went.

Underneath both sits a hand-built harvest harness in Bash and Python: bounded harvest loops, JSON cleaning, dedup-on-merge registries, a visited-URL ledger, and a gated autonomous-coding safety layer.

The safety layer

Autonomous work in this repo runs behind a deliberate gate, configured in .claude/settings.local.json and .claude/hooks/guard_command.py:

  • validate_task.sh — the single allowlisted, offline validation entry point (isolated temp state, mocked agents, no production writes).
  • safe_commit.sh — explicit file lists only; -A, ., and globs are refused.
  • safe_push_main.sh --check — push preflight; the actual push always needs a human.
  • A standing stop-and-ask list: pushing, deploying, external side effects, production state/ writes, anything needing credentials.

Where it stands

The discovery half of this project is essentially complete and well-tested: four topic registries at or beyond target, 231 AX cases with full KPI and evidence fields, a hardened harness, and a real safety gate. Every seed the project knows about has been driven to exhaustion.
