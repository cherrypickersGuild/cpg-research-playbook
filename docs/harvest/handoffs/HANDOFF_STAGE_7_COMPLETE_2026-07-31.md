### 2.3 · S7-2 — the suspicious-URL guard

`base.py`: `SUSPICIOUS_RULE_IDS` · `MigrationInputError` · `GuardMatch` · `suspicious_url_match()` ·

- **Four ordered rule ids, and the order is the precedence** (first match wins):
  `search_engine_host` · `search_query_path` · `feed_path` · `index_page`.

### 2.5 · S7-4 — the dry-run CLI

`scripts/harvest/migrate.sh` is environment and dispatch only — `set -euo pipefail`, `"$@"` forwarded
verbatim, no `eval`, no temp file, no network, no git.

- **`migrate.sh ax-cases` defaults to dry-run** and writes nothing, proved by hashing every file under
  an injected root before and after rather than by trusting `git status`.
- One **deterministic 16-field JSON report** on binary stdout, rendered by the committed
  `artifacts.serialize` — no second serializer. It carries no accepted-record payload, no path, no
  environment or git fact, no bundle path and no publication eligibility.
- **Report family:** `report_type: "ax_cases"` · `report_version: 1` · `operation: "ax-cases"`, with
  **`dry_run` as the sole dry-run/apply discriminator** (E29).
- **Unresolved suspicious URLs still render the complete report** — every rejection, not the first —
  and only then exit non-zero, with stderr naming each case and both ways forward. A reviewed
  `reject` is an acknowledged decision, not an unresolved one.
- **`--allow-unmappable` retains every rejection row and admits nothing**; it never repairs or
  rewrites a URL.
- Override parsing validates the committed shape completely and additionally refuses a review whose
  declared `matched_rule` is not the rule the guard actually fires, or that names a case the guard
  does not refuse at all. The committed file — zero reviews — parses and is never modified.
- **`migrate.sh entity-assess`** exposes S7-1 unchanged: stdout equals the committed assessment byte
  for byte, `--output` writes exactly those bytes, and it migrates nothing.

### 2.6 · S7-5 — atomic apply

`base.py` became the Stage 7 **path owner** — `migrations_root` · `bundle_path` · `manifest_path` ·
`candidate_artifact_path` · `rejection_artifact_path` · `staging_name` · `owns_staging` ·
`validate_run_id` · `MigrationPathError` — deriving paths and **creating none**, every one behind an
anchored run-id pattern so a separator, a `..` or an absolute path never reaches the filesystem. The
ordinary `runs/<run_id>` builders are neither used nor duplicated.

**The published bundle is exactly three files:**

```text
<state-root>/migrations/<run_id>__ax_cases/
├── manifest.json                                        run_manifest.v1.json
├── candidate_output/cases__case-studies__harvest.json    cell_artifact.v1.json
└── rejections/cases__case-studies__rejections.json       rejection.v1.json
```

- **All three documents are constructed and schema-validated before publication** — before a staging
  directory exists at all.
- Writes go to a **unique sibling staging directory** `.tmp_migration_<run_id>_<uuid4hex>` under the
  migrations root; `os.replace` is atomic only within one filesystem, so a system temp directory
  would make publication a copy.
- **Publication is one final same-filesystem directory rename.** The staged path set is asserted to
  be exactly the three, and the destination is rechecked immediately before.
- **No state with only one or two bundle files is observable**: the destination is absent and the
  staging tree complete immediately before the rename, and the complete tree exists immediately
  after.
- **A completed run id is refused before the registry, override or facet input is read** — proved
  with a counting loader whose control case shows both reads would otherwise be recorded. The same
  run id is never overwritten, merged, resumed or treated as idempotent success.
- **Distinct run ids produce separate bundles**, side by side.
- **The exact moving leaves were enumerated by document family** (§2.7).
- Publication eligibility is **derived**: every accepted record must be `not_checked` or bundle
  construction is refused; `publication_eligible` is then `false` with a deterministic reason.
- **Nothing else is created**: no `runs/`, no repository `LATEST_RUN_ID`, no ledger, no topic
  artifact, no coverage artifact, no alias-conflict artifact, no journal, no checksum sidecar, no
  promotion output.
- Cleanup on any `BaseException` removes **only** the staging directory this invocation created,
  proved twice — from the exact retained path and from `owns_staging` — and removes a `migrations/`
  parent only when this invocation created it and it is empty. Five fault-injection boundaries each
  leave the state root path-identical, and a sentinel bundle appearing mid-staging is left
  byte-identical rather than overwritten.
